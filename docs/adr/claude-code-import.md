# Import from Claude Code in one command

- **Date:** 2026-11-17
- **Status:** accepted

## Context

Developers who used Claude Code alone, in a terminal or in VS Code, start Chauffeur empty-handed: their branches in progress, their conversations, their Claude memory and local permissions stay behind. `chauffeur import conductor` ([conductor-import](conductor-import.md)) only serves Conductor users. Claude Code has no workspaces: it keeps sessions by folder (`~/.claude/projects/<folder key>/<session>.jsonl`), usually the developer's main clone, where it switches branches as it goes. One developer's machine showed 43 of 93 sessions changing branch midway, work done in worktrees the session made itself (`.wt/…`, scratchpads under `/tmp`), and nearly every branch a session ended on already merged. Unlike Conductor's, the transcripts are still on disk, so conversations can be resumed natively.

## Decision

Proposed by Théo 2026-11-16, accepted by Justin 2026-11-17: `chauffeur import claude-code` (a daemon method, `claudecode.import`, as `conductor.import`) moves such a developer to Chauffeur in one command (in a later pull request). Three general changes it depends on have their own ADRs: [reactivate-archived-explorations](reactivate-archived-explorations.md), [claude-memory-per-repo](claude-memory-per-repo.md), [clone-local-claude-settings](clone-local-claude-settings.md).

- The sessions active in the last 60 days are read (`--since`, `--all`); sessions still running (`~/.claude/sessions/<pid>.json`) are refused, and folders that are not git repos are skipped with a warning.
- A session's branches come from what it wrote: its Write, Edit, MultiEdit and NotebookEdit paths, each resolved to its git worktree, then to a repo and a branch (its own folder counts only if written to), plus the branches its shell commands created (`git worktree add -b`, `git switch -c`, `git checkout -b`).
- A branch that exists and is not merged into the default branch is live, however old; uncommitted changes in a checkout make it live too. A live branch becomes a workspace on that branch, the session its chat; the same live branch in several repos makes one workspace with those repos.
- A session with two live branches or more becomes a parent workspace on its folder's repo, on a new branch named from the session title, holding its chat, with one child workspace per live branch. A branch written by two such sessions goes to the most recent one's parent; a session that wrote only on a child's branch becomes a chat of that child. The parent's chat is told to follow its children with `chauffeur status`, `wait` and `send`.
- Uncommitted changes on a clone's default branch become a workspace on a new branch carrying them (the parent's, in an orchestration).
- Everything else (default branch, merged, deleted, detached) lands in one history exploration per repo, the one of the repo the session ran in, checked out at its base branch, as closed tabs, resumable read-only. A later run adds the sessions it finds to that exploration; once it is archived, to a new one (decided with Théo 2026-11-20).
- A live branch checked out in the clone or in one of the user's own worktrees is released as the Conductor import does: HEAD detached on the same commit, uncommitted and untracked changes copied into the new worktree, after one confirmation defaulting to no (`--yes` skips it); the output says how to clean the clone. With `--move-changes`, the changes are also saved in a git ref kept 30 days and the checkout goes back to its default branch. A worktree under `/tmp` half deleted by its cleanup carries its branch's commits only, never its diff. Each repo's clone is Chauffeur's; with none, the user's holding the branch becomes it, named for that repo alone. When Chauffeur has a clone of its own, the branch is fetched there instead and the user's checkout keeps it, its changes copied. No branch is released where a Claude Code session still runs, and a later run adds the sessions found on an imported branch to its workspace.
- `--dry-run` prints the whole plan and changes nothing; `--json` gives the plan and the result. Per-session picking is left for a V2.
- Each session is copied, never moved, with the same session id into the folder its chat runs from, by the sidecar: its transcript and its whole folder (subagents, tool outputs…), streamed whatever its size, no link in it followed (Claude Code's own folder may be reached through one), never replacing a different file (`context.copy`; capture and restore, which cloud transfers use, hold a session in memory and refuse the longest ones, over 64 MB: decided with Théo 2026-11-20); the original stays usable in the terminal and VS Code, and the output says the two copies no longer sync. The conversation shown in the app is read through the SDK and mapped by `ClaudeEventMapper`, as subagents' transcripts are. Imported session ids are recorded: a second run imports none twice, even after archiving.
- The first resume of an imported chat tells its agent which folders are the user's, where the repo now lives, and that its folder is the workspace's.
- A repo with no setup script gets one guessed from its root lockfile (pnpm, npm, yarn, bun, uv, poetry, bundle), shown in the dry run and written to the user's `[repos.<name>.scripts] setup`, never into the repo. Local-scope MCP servers are named in a warning (names only) with the `claude mcp add --scope user` command.
- **No agent of any workspace writes into a source clone**: the worktrees are made from the user's clones, and nothing else stops an agent from changing the clone itself. Every Claude chat of a workspace (explorations and design chats included; Codex and Mistral Vibe chats in a later pull request) refuses Write, Edit, MultiEdit and NotebookEdit into one of the workspace's clones, naming the matching path in its worktree. A shell command that names a clone (a path in it, a folder holding it, or the clone as the folder it runs in) is refused unless it is a read the guard knows (`cat`, `grep`, `ls`, `find` with no action, `git status`, `log`, `diff`…), a copy out of the clone, or a write it can place outside; a redirection into a clone is refused whatever the command, and so, on a line naming a clone, is a command that may change files with a value only known as the line runs (a variable, a command's output, `xargs`' input). The writes git makes in a clone's `.git` for a worktree (a commit from it) stay allowed; git run from the worktree that deletes, renames, force-moves, rebases, switches onto or fetches into the clone's checked-out branch or its default branch, or changes the repo's settings, remotes, refs, reflogs, stashes (`clear`, `drop`: decided with Théo 2026-11-21) or other worktrees (`git branch -D main`, `git config user.email`, `git remote set-url`, `git fetch origin main:main`, `git gc`, `git worktree prune`…), its `.git` being shared, is refused, naming what it protects; commits, the workspace's own branches, rebases, pushes, stashes and tags run as before. A refusal costs little: the worktree holds the same files. An imported chat's guard also covers the checkouts its session ran or wrote in (its own worktrees, scratchpads) of the workspace's repos, each naming the matching path in the repo's worktree; one of another repo is not covered. A setting to turn the guard off only if a need shows.

## Consequences

- The import reuses the Conductor import's repo matching by remote, clone reuse, branch release, change copy, dry run and idempotence; reading and placing Claude Code sessions is new (in a later pull request).
- The sidecar gets the workspace's clones with their worktrees at each session start, and a `PreToolUse` guard (`sidecar/src/guard/clone-guard.ts`) reads file tools' paths, and shell commands as the shell reads them (`shell-line.ts`: quotes, substitutions, here-documents, `bash -c`, `eval`, wrappers, the line's variables). It allows what it knows to be a read rather than refusing what it knows to be a write, since no list of writes is ever complete. A guard rail, not a sandbox: a program whose own code writes into the clone, the command line not naming it (a script, a build step run from elsewhere), is not caught; explorations' and design chats' shell commands also run in Claude Code's OS sandbox, which keeps them out of the clones whatever they are. It covers Claude chats first; Codex and Mistral Vibe chats get it in a later pull request. Meanwhile a Codex chat's sandbox writes in the workspace's folders only, a write elsewhere, a clone included, needing an approval (the user's, or Codex's reviewer in auto mode; none in bypass-permissions mode, which has no sandbox); a Vibe chat is not guarded.
- The import ships in steps behind a switch, turned on once workspaces, history, orchestrations and the resume note are in; the guard ships first, for every workspace.
- Rewind checkpoints (`~/.claude/file-history/`) are not carried; Chauffeur launching an agent to write a setup script was rejected.
