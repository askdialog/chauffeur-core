# 0037. Local models through Ollama

- **Date:** 2026-10-29
- **Status:** accepted

## Context

Agents should keep working where the network is poor or absent (asked by a user).

## Decision

Copied from `docs/SPEC.md`, where it was recorded as settled with Justin; the date of each part is in its text.

From `SPEC.md`, story 52:

> As a developer, I want chats on a model that runs on my own machine, picked in the model picker like any other, so that I keep working where the network is poor or absent, in a train say (asked by a user; decided with Justin 2026-10-29). A local model is a Codex chat whose model Ollama serves: everything a Codex chat does (sandbox, permissions, guards, `delegate`, resuming) works the same. Chauffeur runs Ollama itself: it starts it when a local chat or the settings need it and stops it once nothing uses it; Settings › Local models downloads (with its progress) and deletes models, and says how to install Ollama when it is missing (`chauffeur ollama`). A local model is slower and weaker than a hosted one: on a 48 GB M5 Pro, Qwen3.8-27B did a small task right in about 16 minutes where gpt-oss-20b could not edit a file (`.chauffeur/offline-bench` of the workspace `lire-le-fil-slack-partage`, 2026-10-28). What needs the network otherwise (titles, Linear, `gh`, plan usage, MCP servers) is a later step.

From `SPEC.md`, Local models:

> **Local models (story 52, decided with Justin 2026-10-29).**
> - A local model is a Codex model whose id is `ollama/<name>` (`ollama/qwen3.8`, `ollama/glm-4.7-flash:q8_0`): `models.list` appends to Codex's catalog every model Ollama keeps on disk, read from its manifests (`$OLLAMA_MODELS`, else `~/.ollama/models`, `manifests/<registry>/<namespace>/<name>/<tag>`; the default registry and namespace and the `latest` tag left out of the name), its size the sum of its layers, no effort, no fast mode. Reading the manifests starts nothing: opening the picker never starts Ollama. The app shows them under Codex, named `<name> (local)`.
> - The sidecar opens such a chat's thread with `modelProvider: "ollama"` and the model's name (Codex's built-in Ollama provider, `127.0.0.1:11434`, no OpenAI login needed), `model_context_window` 65,536 (the context the daemon gives Ollama), and drops Codex's warning that it has no metadata for the model. Its Codex runs apart from the user's `~/.codex`, in a `CODEX_HOME` the daemon makes for local models (`codex-local` in the state folder, 0700; a fork's too): with the user's config, Codex brings every MCP server, plugin and app, and for a model it has no metadata for puts all their tools in the prompt, about 256,000 tokens on one developer's machine, past any local model's context (offline they would not answer anyway); apart, the first prompt is about 10,000 tokens. So a local chat has none of the user's MCP servers, plugins, skills or instructions, and no repo's `.codex` layer (that Codex trusts no repo; the chat says nothing of it), but keeps the repos' skills, which Chauffeur gives it, and the workspace's AGENTS.md. Codex takes the provider only when a thread starts or resumes, never at a turn: once a chat's session has started, `chat.configure` refuses a model on the other side (hosted to local or back) with "start a new chat"; before, the chat takes either.
> - Installing Ollama (decided with Justin 2026-10-29): Chauffeur installs its own, pinned like the agents (0.40.11, the version tried; an upgrade is a deliberate change of the version and its checksums in the daemon), on macOS and Linux: `ollama.install` downloads Ollama's release archive from GitHub (`ollama-darwin.tgz`, 181 MB; `ollama-linux-amd64.tar.zst` or `-arm64`, about 1.5 GB with its CUDA libraries, not the ROCm or Jetson builds), checks it against the SHA-256 written in the daemon, unpacks it (in the daemon: no `tar` or `zstd` of the system needed; nothing written outside its folder) into `ollama/<version>/` of the state folder, and removes another version there and the download; `ollama.status` follows the download, the check and the unpacking. Elsewhere (another system or processor) it is refused, and the command that installs Ollama is shown. Settings › Local models offers it when no Ollama is found ("Install Ollama", with its size), `chauffeur ollama install` always.
> - Ollama: Chauffeur's own copy when installed, else `ollama` found on the login shell's PATH, else `/opt/homebrew/bin`, `/usr/local/bin`, the Ollama app's `Contents/Resources` (tests give a fake one, its address and its models folder). Before it hands a message to a local chat (a session to start or a live one), and for a pull or a delete, the daemon makes sure something answers at `127.0.0.1:11434` (`/api/version`): an Ollama already running there (the user's app or service) is used as is and never stopped; otherwise the daemon starts `ollama serve` in a process group of its own, its output in `ollama.log`, with `OLLAMA_CONTEXT_LENGTH=65536` (Codex's prompt alone is about 10,000 tokens; Ollama's default context truncates it), `OLLAMA_NOPRUNE=1` (a start must not delete an unfinished download), flash attention and a q8 KV cache, and waits for it (20 s at most). The one it started is stopped once no model has been loaded (`/api/ps`) and no pull has run for `idle_session_minutes`, and when the daemon stops. Missing, the chat's message fails and says to install it from Settings › Local models or with `chauffeur ollama install`.
> - `ollama.status` (whether it is installed and where, whether it runs and whose, the models on disk with their size, the pulls in progress with their progress or their error), `ollama.pull {model}` (in the background, Ollama's `/api/pull`; a second pull of the same model is refused while one runs), `ollama.delete {model}` (`/api/delete`). Clients poll `ollama.status` for a pull's progress, as they do for an update. `chauffeur ollama [install | pull <model> | rm <model>]`.
> - Settings › Local models: Ollama's state, and Install (its progress) when it is missing; the models on disk, each with its size and Delete (asked first); a field to download one by name with the models we tested suggested (Qwen3.8-27B first), and each pull's progress; a note that a local model is slower and weaker than a hosted one.
> - Not yet (the later step of story 52): titles, briefs and `delegate` still ask hosted models, and Linear, `gh`, plan usage and MCP servers still say they fail without the network.

## Consequences

A local model is a Codex chat on Ollama, run apart from the user's `~/.codex`; Chauffeur installs a pinned, checksummed Ollama. Titles, briefs, Linear, `gh`, plan usage and MCP servers offline are a later step.
